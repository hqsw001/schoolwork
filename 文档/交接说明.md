## 六、容易踩的坑（都是真踩过的）

### 环境类

- **`pwsh` 的 `cd` 不持久** —— 用 `workdir` 参数，别靠 `cd`。
- **控制台中文乱码是显示问题，不是数据损坏** —— 设置 `PYTHONIOENCODING=utf-8`。
- **`messagebox` 是模态的，会一直等用户点"确定"。** 测试里必须把它换成假的，
  否则整个套件会卡住（AI 套件曾因此从 12 秒变成 160 秒）。
- **`tk_popup`（右键菜单）也是模态的**，测试里调用会卡住。
- **Tk 会把 lambda 的内存地址写进绑定脚本**，所以"重新绑定后脚本字符串相等"
  这个断言永远不成立。判断有没有绑上只能看**绑定是否为空**。
- **`winsound` 不支持 `SND_MEMORY | SND_ASYNC`**（抛
  "Cannot play asynchronously from memory"），而且**播 60ms 的声音也会阻塞
  200~600ms**。提示音因此走"后台线程 + 连发合并"。
- **`winsound.PlaySound` 是进程级的**，多线程同时播只会互相打断。

### 设计类

- **`settings.set` 拒绝未登记的键**（抛"未知配置项"）。所以配置项**必须**
  逐个登记到 `defaults.SPECS`，用前缀拼出来的动态键存不进去。
- **`get_history` 的 `total` 是整个库的条数**，不随类型筛选变化；
  分页靠 `len(items)` 判断。（我在这上面写错过断言。）
- **图片/文件类记录的 `content` 是磁盘路径**，所以：加密时不碰这两类、
  文本清洗时也不碰（`is_file_type()` 而非直接比 `"file"`）。
- **解密入口集中在仓储层的 `_row_to_entry` 一处** —— 所有读路径都从这里走。
- **敏感记录的正文在库里是密文**，SQL `LIKE` 匹配不到，
  所以检索要补一遍内存匹配。
- **`_unregister_*` 只动 `_registered`/`_effective`，不清 `_hotkeys`。**

### 流程类

- **改完代码先跑 `tests.static_check`**（见上）。
- **测试改了全局状态就必须还回去。** 曾因为新用例调用粘贴流程（顺手收起了
  面板），导致后面依赖"面板当前是显示的"的两个用例莫名其妙失败 ——
  失败出现在离现场很远的地方。
- **有些断言是"看鼠标脸色"的。** `preview_check` 的「初始不可见」就栽过：
  面板默认出现在"水平居中、纵向 13%"处（本机 2048×1152、面板 470×640 →
  `x∈[789,1259] y∈[149,789]`），**鼠标停在那儿时**，窗口在鼠标底下映射出来的
  瞬间就触发了卡片 hover，延迟到点后预览浮窗自己弹出来，断言必失败。
  跟代码一点关系都没有，纯粹取决于跑测试的人鼠标停在哪儿。
  已经修掉（section 5 先把面板挪到"鼠标的对面"，并加了一条前置条件断言）。
  **教训**：涉及"初始状态"的断言，先让它不依赖光标位置。
- **`run_tests.py` 会给子进程设 `CLIPBOARDPRO_LOG_LEVEL=WARNING`**（防刷屏）。
  所以任何**靠日志内容做断言**的套件，必须自己显式把它设回 `INFO` 再启子进程，
  否则本机单独跑能过、进了全量回归就失败 —— `packaging_check` 就这么栽过一次。
- **`edit` 工具的 `old_string` 带尾换行、`new_string` 不带，会把两行粘成一行。**
  这个错误在本工程里犯了十几次，每次都要读回文件才发现。改完记得读一眼。
- **永远不要写 `check(True, "...")` 这种恒真断言** —— 等于没测。
  （"浮窗不抢焦点"那条一度就是这么写的，改成真去读源码查调用之后，
  当场报了一次假阳性：文档字符串里正好写着"不调用 focus_force"。）
- **跑全量回归之前，先确认没有实例在跑。** 本程序是常驻托盘的，前一个会话
  留下的实例会一直占着全局快捷键（`RegisterHotKey` 先到先得）与单实例互斥体，
  热键类套件会被它搞失败，打包版的启动验证也会被单实例守卫拦下。
  查法：`Get-Process | Where-Object { $_.ProcessName -match 'python|剪贴板' }`；
  兜底清法：`taskkill /PID <id>`（不带 `/F`，让它自己注销快捷键与托盘），
  不行再 `/F`。**注意 `taskkill` 不带 `/F` 对它是无效的** —— 面板窗口收到
  `WM_CLOSE` 只会"收起"，进程仍然活着，最后还是要 `/F`。

双击即用，目标机器**不需要装 Python / pillow / pywin32**。

### 为什么是文件夹版而不是单文件 exe

单文件 exe 每次启动都要把整个运行时解压到 `%TEMP%`，冷启动要等好几秒。
这个程序是**常驻托盘**的，启动慢会被用户当成"没启动起来"。文件夹版启动快、
报错信息完整，代价是分发时必须整个文件夹一起拷（**只拷 exe 跑不起来**）。

### 打包踩的三个坑（都不会报错，只"表现得很怪"）

打包之后 `__file__` 指向的是**解包目录**（`_internal`）而不是 exe 所在目录，
`sys.executable` 也变成了 exe 自己。三处算错都不会抛异常：

1. **数据目录按 `__file__` 算** → 落到 `_internal\.data`。用户把文件夹换个位置、
   或者用新版整个覆盖旧版，历史记录看起来就"丢了"。
   → 现在按 **exe 所在目录** 算（`paths.program_root()`）。
2. **自启命令还拼"解释器 + 启动脚本"** → 注册表 `Run` 里那条命令指向打包后
   根本不存在的 `启动剪贴板Pro.py`，**开机自启静默失效**，而界面上还显示"已开启"。
   → 打包形态直接返回带引号的 exe 路径。
3. **随包资源按 exe 所在目录拼** → `emoji_data.json` 永远读不到，
   表情面板静默降级成**两张兜底分组**，功能"看起来有、其实是残的"。
   → 现在按 `sys._MEIPASS`（`paths.bundle_root()`）算，
   打包脚本把 json 放到 `_internal\app\data\` 这个同样的相对位置。

> 以后要加随包资源，必须同时改 `build_exe.py` 的 `--add-data` 与
> `paths.bundle_root()`，两边对不上就是上面第 3 条。
