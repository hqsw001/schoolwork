# 剪贴板Pro 运行说明

面向"拿到这份代码、想在自己的 Windows 机器上跑起来"的人。
不需要任何开发经验，按顺序照做即可。

---

## 一、装 Python

1. 到 <https://www.python.org/downloads/windows/> 下载 **Python 3.10 或更高版本**
   （本项目在 3.12.5 上实测通过）
2. 安装时**务必勾选 `Add python.exe to PATH`**（这是最容易漏的一步）
3. 装完打开"命令提示符"，输入下面这行确认：

   ```bat
   python --version
   ```

   能看到 `Python 3.12.x` 之类的输出就对了。

---

## 二、装两个依赖库

```bat
python -m pip install pillow pywin32
```

| 库 | 用途 | 能不能不装 |
|---|---|---|
| `pillow` | 图片处理：剪贴板位图解码、图片像素指纹、缩略 | 不能。装不上时图片类内容会被跳过，文本仍可用 |
| `pywin32` | 剪贴板读写（`win32clipboard`） | 不能 |

其余用到的全是 Python 标准库（`tkinter`、`sqlite3`、`ctypes`、`hashlib`、`json`、`re`），
不需要 Node、Rust、MySQL 之类的东西，**也不需要联网**。

## 三、启动

### 方式一：双击（推荐给日常使用）

双击 `启动剪贴板Pro.bat`。启动器会检查环境并打印进度：

```
[1/3] 已找到 Python 3.12.5
[2/3] 依赖库检查通过
[3/3] 正在启动（后台驻留，不占用本窗口）...
  已启动，进程号 12345
  本窗口可以直接关闭，程序会继续在后台运行。
```

打印完提示后黑窗口会**自动关闭**，这是正常的 ——
程序已经脱离终端在后台运行了。

> **关掉终端不影响程序。** 托盘图标和全局快捷键都还在。
> 这是刻意设计的：Windows 上控制台程序默认会随终端一起被杀，
> 启动器专门做了脱离处理（原理见 `文档/设计说明.md` 第十一章）。

### 方式二：命令行（排查问题时用）

```bat
cd <解压目录>\1st
python -m app.main --show
```

这种方式程序会**跟着这个终端一起退出**（Windows 的默认行为），
所以日常使用请用方式一。

想看启动到底发生了什么、又不想脱离终端：

```bat
cd <解压目录>\1st
python 启动剪贴板Pro.py --wait
```

### 不要重复启动

启动器做了**单实例保护**：已经有实例在跑时，第二次启动会被拦下，
并尝试把已有的面板叫到前台；叫不动就弹一个提示框。

这是为了避免重复启动抢占全局快捷键 —— `RegisterHotKey` 是先到先得，
第二个实例拿不到快捷键却占着托盘图标，表现就是"快捷键时灵时不灵"。

> 如果提示"已经在运行"但你就是看不到面板：
> 按一下 `Ctrl+Shift+V`，或单击任务栏右下角的托盘图标。

> ⚠️ 如果双击后**黑窗口一闪就没了、程序也没起来**，那是另一个问题：
> 启动器脚本的换行符被改成了 LF（cmd 只认 CRLF）。
> 一条命令自查：`python tests\check_launchers.py`，
> 详见下面的 Q0。

### 命令行参数

| 参数 | 作用 | 什么时候用 |
|---|---|---|
| `--show` | 启动后立刻显示主面板 | 第一次用、想确认它起来了 |
| 不加参数 | 静默启动，只驻留系统托盘 | 日常使用 |
| `--no-listener` | 不注册剪贴板监听与全局快捷键 | 只想调界面、不想让它记录你复制的东西 |
| `--data-dir "D:\某目录"` | 换数据目录 | 想把数据放别处、或开第二个实例做对比 |

## 四、第一次使用

启动后程序**没有主窗口**，这是正常的——它在系统托盘里待命。

1. **唤出面板**：在任意软件里按 `Ctrl+Shift+V`
   （也可以双击托盘图标）
2. **让它记录**：随便复制几段东西——一段文字、一个网址、一段代码、一张截图都行。
   面板里的卡片会自动出现，不用手动刷新。
3. **粘贴回去**：先切回你刚才在用的软件，按 `Ctrl+Shift+V` 唤出面板，
   **双击**你想粘的那条（或选中后按回车）。
   面板会自动收起，内容直接出现在你的光标位置。

### 面板窗口怎么操作

面板是一个**标准 Windows 窗口**（带标题栏），不是那种没有边框的浮层，所以：

| 想做什么 | 怎么做 |
|---|---|
| 移动面板 | 拖标题栏 |
| 调整大小 | 拖窗口边缘（大小会被记住，下次打开还是这么大） |
| 最小化 | 标题栏的最小化按钮，或面板里的 `—`，或按 `Ctrl+M` |
| 收起面板 | 标题栏的关闭按钮、面板里的「收起」、`Ctrl+W` 或 `Esc` |
| 打开设置 | `Ctrl+,` 或点面板里的「☰ 操作」 |
| 让面板不再总在最前 | 设置 → 窗口行为 → 取消勾选「面板总在最前」 |

> **点关闭 ≠ 退出程序。** 关闭只是把面板收起来，程序仍在托盘运行，
> 快捷键随时可以再唤出来。真正退出请用**托盘图标右键 → 退出**。
> 这样设计是因为剪贴板管理器要一直待命才能记录，
> 误点一下关闭就整个退出会很难用。

### 键盘操作

| 按键 | 作用 |
|---|---|
| `Ctrl+Shift+V` | 唤出 / 收起主面板 |
| `Ctrl+Shift+F` | 唤出面板并聚焦搜索框 |
| `↑` `↓` | 上下选择 |
| `Enter` 或 双击 | 粘贴选中项 |
| `Ctrl+1` ~ `Ctrl+9` | 直接粘贴当前列表第 1~9 条 |
| `Ctrl+P` | 置顶 / 取消置顶 |
| `Ctrl+E` | 编辑这条内容 |
| `Delete` | 删除选中项 |
| `Ctrl+F` | 聚焦搜索框 |
| `Ctrl+W` | 收起面板 |
| `Ctrl+M` | 最小化 / 从最小化还原 |
| `Ctrl+,` | 打开设置 |
| `Esc` | 收起面板 |
| `F5` | 刷新列表 |
| 右键卡片 / 点"☰ 操作" | 打开完整菜单 |

### 托盘图标（右键）

- 显示主面板
- 暂停监听 / 恢复监听（**输入密码前建议先暂停**）
- 清空历史
- 设置
- 退出

> 左键单击托盘图标 = 显示主面板。

## 五、数据存在哪

默认全部放在 `1st\.data\` 目录：

```
.data/
├── clipboardpro.db       SQLite 数据库：历史记录、标签、配置
├── clipboardpro.log      运行日志（出问题时先看这个）
└── attachments/          图片附件
```

- **纯本地**，程序不联网、不上传任何内容
- 想整体备份：直接拷走 `.data` 目录
- 想彻底清空：删掉 `.data` 目录（下次启动会自动重建）
- 想换位置：`--data-dir "D:\clipboard-data"`，
  或设环境变量 `CLIPBOARDPRO_DATA_DIR`

## 六、常见问题

### Q0：双击 `启动剪贴板Pro.bat`，黑窗口一闪就没了，程序也没起来

**这是本项目真实发生过的一次事故，原因和解决办法如下。**

`cmd.exe` 解析 `.bat` 时**不认孤立的 LF（0x0A）行尾**。
文件里只要有中文这类多字节字符，cmd 就会把行尾判断错，
把下一行"粘"到上一行上——于是 `python -m app.main` 这一行
被吞进了上一条命令的参数里，程序从未被启动，脚本自己跑完就退出了。

任何编辑器（VS Code、Notepad++、Git 的 `core.autocrlf`）都可能
在保存或 checkout 时把这个文件的行尾从 CRLF 改成 LF。

**怎么确认：**

```bat
cd <1st 目录>
python tests\check_launchers.py
```

有问题会直接告诉你：

```
[有问题] 启动剪贴板Pro.bat
    - 存在 87 处孤立 LF 换行（CRLF 只有 0 处）：cmd 不认 LF 行尾，
      会把下一行粘到上一行，导致启动命令被吞掉。请把整个文件转成 CRLF 换行
```

**怎么修（任选一种）：**

- 用 VS Code 打开该文件 → 右下角点击 `LF` → 改成 `CRLF` → 保存
- 用 Notepad++ → 编辑 → 档案格式转换 → 转换为 Windows 格式（CRLF）→ 保存
- 或者干脆绕过启动器，直接命令行启动：

  ```bat
  cd <1st 目录>
  python -m app.main --show
  ```

**怎么避免再犯：** 仓库根目录的 `.gitattributes` 已经为 `*.bat` 声明了
`eol=crlf`；另外 `run_tests.py` 每次都会跑这个检查，改坏了会被测出来。

### Q1：按 `Ctrl+Shift+V` 没反应

按顺序排查：

1. **先看面板底部状态栏显示的快捷键是什么。**
   如果显示的不是 `Ctrl+Shift+V`，说明这个组合**被别的程序占用了**，
   程序已经自动换了一个键并弹过提示 —— 状态栏里显示的就是真正生效的那个。
   按它显示的键即可，也可以在「设置 → 快捷键」里自己指定。
2. **程序到底在不在跑？** 看任务栏右下角有没有托盘图标
   （Win11 上可能被折叠进 `∧` 溢出区里）。
   没有的话说明程序没启动或被退出了，重新双击启动器即可。
3. **你刚才是不是关掉了启动器的黑窗口？** 关掉终端本身不影响程序
   （启动器专门做了脱离处理）。但如果是从命令行 `python -m app.main`
   启动的，关掉那个终端程序就会一起退出 —— 改用启动器双击启动。
4. 兜底：**单击托盘图标**同样能唤出面板，快捷键坏掉不影响使用。

### Q1b：面板看起来"消失"了，但程序还在

大概率是**最小化了**，或者被**收起了**。

- 收起了 → 按快捷键，或单击托盘图标
- 最小化了 → 点任务栏上的「剪贴板Pro」按钮，或按 `Ctrl+M`
- 被别的窗口盖住了 → 设置 → 窗口行为 → 勾上「面板总在最前」

### Q1c：想知道是哪个程序占用了快捷键

Windows 没有提供"谁占了这个热键"的查询接口。实用办法：

1. 打开「设置 → 快捷键」，点一下主面板那个框，按一组新的组合键；
2. 还是提示被占用就再换一组；
3. 常见的占用者：输入法（尤其 CJK 输入法的切换键）、截图/录屏工具、
   IDE 与编辑器的快捷键、浏览器扩展、以及**其他剪贴板管理软件**
   （如果你之前装过 Ditto / 微软自带剪贴板历史等，先把那个退掉）。

实在懒得查：直接用程序自动换好的那个键就行。

### Q2：复制了东西但列表里没有

1. 看面板底部状态栏，如果显示 **"已暂停"**，说明监听被暂停了——
   托盘菜单里选"恢复监听"，或按设置里的暂停快捷键。
2. **图片和文件**要等一会儿（要做解码和存附件），大约半秒。
3. 如果是**从某个软件复制的特殊格式**（比如带图层的设计稿），
   程序可能读不出来，这种情况会静默跳过并记进日志，不会打扰你。
4. 看 `.data\clipboardpro.log`，日志里有明确的跳过原因。

### Q3：粘贴没粘上，或者粘到了别的地方

这是最典型的"焦点没交还成功"。程序按四级策略尝试把焦点还给你的原窗口
（直接切换 → Alt 键技巧 → 附加输入线程 → 最小化再还原），
绝大多数软件都没问题。如果还是不行的场景，请记录：

- 你正在用的是什么软件（软件名 + 版本）
- 面板底部有没有弹"已复制到剪贴板，请手动按 Ctrl+V 粘贴"

**出现这个提示时，内容已经在剪贴板里了，你手动按一下 `Ctrl+V` 就行。**
麻烦把上面两条信息告诉我，我按软件逐个补特例。

### Q3b：复制了一张图片，怎么把它变成文件存到文件夹里？

先分清两件事，答案不一样：

**① 把图片粘到文档里**（Word、画图、微信、PPT…）
选中那条图片记录，**双击**（或按回车）。程序把图片写回剪贴板并自动按
`Ctrl+V`，图片就出现在光标位置了。

**② 把图片粘到文件夹里**（想得到一个 `.png` 文件）
在图片记录上**右键 → 「复制为文件（可粘贴到文件夹）」**，
然后到目标文件夹里按 `Ctrl+V`，就得到一个 PNG 文件。

> **为什么不能直接双击来粘进文件夹？** 因为在文件夹里按 `Ctrl+V` 时，
> 资源管理器只认"文件列表"格式，不认"位图"格式——直接把一张图双击
> 粘过去，它会什么都不做。这不是本程序的缺陷，是 Windows 的规矩。
> 所以图片记录多给了「复制为文件」这一项，它换成资源管理器认识的格式。

两种方式拿到的是同一张图，且与当初复制进来的原图**逐像素一致**。

### Q4：为什么我复制了两遍同样的内容，只有一条记录

这是**设计如此**——「重复内容合并」：相同内容只留一条，
把它刷新到列表最前、使用次数加一，不会刷屏。

不想要这个行为：设置 → 采集与去重 → 取消勾选"重复内容合并"。

### Q5：为什么我的手机号在列表里变成了 `138****5678`

这是**敏感信息脱敏**（防止共用电脑、投屏时泄露）。
**点开这条记录看全文，原文还在，没有丢。**

不想要：设置 → 隐私与安全 → 取消勾选，或只勾选你关心的类型。

> ⚠️ 注意：**当前版本敏感内容在数据库里仍是明文存储**，
> 加密落盘还没做（排在下周）。请勿在共用电脑上用这个版本存密钥。

### Q6：面板跑到屏幕外面了 / 面板太大或太小

面板默认在屏幕水平居中、靠上的位置弹出，**并且会记住你调过的窗口大小**。

尺寸异常时的处理：

1. 直接拖窗口边缘调整到你想要的大小，收起时会自动记住；
2. 如果窗口大到拖不动（上次在 4K 屏幕上调的），删掉配置里的记录即可：
   设置 → 恢复默认设置（不影响历史记录），
   或者直接删掉 `.data` 目录重新开始；
3. 程序在恢复尺寸时会自动做一次"夹到当前屏幕范围内"的检查，
   所以换成小屏幕也不会出现完全够不着的窗口。

> 面板位置不记忆是刻意的：它是"停靠式"工具，固定从屏幕中上部弹出来更好预期。
> 如果连位置一起记，偶尔拖到副屏之后，下次在单屏环境下打开就会出现在屏幕外。

### Q7：怎么让它开机自启

当前版本还没做开机自启开关。手动做法：

1. 按 `Win+R`，输入 `shell:startup`，回车
2. 把 `启动剪贴板Pro.bat` 的**快捷方式**拖进去

> 开机自启时启动器会弹一个黑窗口再自动关掉（一闪而过）。
> 如果希望完全无感，也可以直接给 `pythonw.exe` 做快捷方式——
> 但注意 `pythonw` 在含中文的路径下启动会失败（本项目路径就含中文），
> 所以还是推荐用 `启动剪贴板Pro.bat`。

### Q8：数据能导出、能换机器吗

可以。整个 `.data` 目录拷到新机器的同一位置即可
（数据库、附件、配置都在里面）。

## 七、卸载 / 完全清理

1. 托盘图标右键 → 退出
2. 删掉整个 `1st` 目录
3. 如果改了数据目录，把那个目录也删掉

程序不写注册表（除了你自己加的开机自启项）、不装服务、不装驱动，
删目录即彻底卸载。

## 八、想自己跑测试

```bat
cd 1st
python run_tests.py --all
```

会依次跑 7 个测试套件（会短暂弹出窗口、占用系统剪贴板，
其中一个会启动记事本并往里面粘一段字，结束后自动关闭）。

只跑不碰系统剪贴板的部分：

```bat
python run_tests.py --safe
```
